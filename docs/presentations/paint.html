Game · shipping today

Paint

An MS-Paint-style freehand drawing app on the STM32F411 — move a cursor with the joystick, hold to paint in any of six colours, onto a canvas that persists in a full-screen framebuffer.

What it is

A persistent drawing surface backed by a 128×160×16-bit framebuffer (40 KB). Painting writes colour into the buffer; the display is kept in sync by repainting the small area the cursor just vacated — a hand-rolled dirty-area redraw on a chip with no GPU.

How it works

  • Joystick moves a 10×10 cursor (with a movement threshold to settle jitter).
  • Hold to paint, release to hover; one button cycles the palette, one clears.
  • A live swatch shows the active colour; the cursor composites over the saved canvas.
128×160 ST7735 · exact RGB565 palette · open live ›

Skills demonstrated

Hand-written ST7735 driver Full-screen 40 KB framebuffer (persistent canvas) Dirty-area restore / redraw 6-colour RGB565 palette + cycling Button state machine (paint / hover / clear / cycle) Debounced input via timed delays Cursor compositing over a saved buffer UI region masking (swatch quarantine) 12-bit ADC joystick sampling + deadzone

Shipping today — MVP

  • Freehand painting with hold-to-draw / hover
  • Persistent canvas in a 40 KB framebuffer
  • Six-colour palette with one-button cycling
  • Full-screen clear / reset

Where it’s headed — Full release

  • Undo / redo (cheap once RAM isn’t the limit)
  • Save / load drawings to flash
  • Flood-fill, adjustable brush size, true white eraser
  • Larger palette / colour picker
  • DMA blit so fast strokes never outrun the redraw
  • Exit-to-shell as a console cartridge

Proof-of-concept framing

The indirect render — painted pixels reach the panel only when the cursor moves off them — is a deliberate MVP simplification that proves the framebuffer-persistence model on a constrained MCU. On the RP2350’s 520 KB RAM, multiple buffers (undo, double-buffering) become trivial, so the “missing” features are roadmap, not rework.
