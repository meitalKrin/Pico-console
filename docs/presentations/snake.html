Game · planned · reference cartridge

Snake

The third game — built greenfield, natively to the console’s game-module contract, so it doubles as the reference implementation that proves the cartridge model.

What it is

Classic grid Snake: steer a growing body around an 8 px cell grid, eat food to grow, avoid the walls and yourself, ramp up speed as you lengthen. It is deliberately the first game written to the contract — init / update / render / teardown — rather than owning its own main().

Why it leads the refactor

  • Its body is a proper linked list / ring buffer with correct node lifecycle…
  • …which fixes spaceShip’s unbounded-heap bug by design, as a worked example.
  • Food spawns from the shared seeded RNG — fair and reproducible.

Skills it will demonstrate

Game-module / cartridge lifecycle contract Linked-list / ring-buffer body with correct lifecycle Shared seeded RNG service Grid model + dirty-cell rendering Self / wall collision Speed ramp via shared scheduler Flash high-score persistence Built on the shared input / display HAL

MVP target

  • Grid movement, growth, food, self/wall collision
  • Score + speed ramp
  • High score saved to flash
  • Runs as a cartridge under the shell

Where it’s headed — Full release

  • Levels / maze obstacles
  • Wrap-around mode
  • Two-player / versus
  • Cosmetic skins & themes

Proof-of-concept framing

Snake is the deliberate “do it right” cartridge: it takes the linked-list pattern Spaceship introduced and gives it the disciplined lifecycle the MVP skipped. Shipping Snake on the contract is what turns “three separate firmwares” into “a console with a reusable game template.”
